# Project `05-jsp`

Introduces JSP syntax.

## JSP Architecture

JSP is like a web resource exactly how a Servlet is.

In fact, when a request for a JSP resource hits the server, the **JSP Container**
part of the server (Tomcat, Jetty, etc.) will:
1. Translate the JSP file into a Servlet java file, which is called a
    **JSP Generated Servlet**.
1. Compile it, and create the bytecode (.class file).
1. Ask JVM to load the class.
1. Run the initialization lifecycle of this generated Servlet *ONCE*. That is,
    create a single object — one single object that caters to all requests to
    this JSP resource (same with plain Servlets) — and call the `init()` method
    on this object.
1. Above steps (1-4) happen only for the first request for this particular JSP
    resource. For subsequent requests, step 6 below happens directly.
1. The `service(req, res)` method is invoked on every request (including the
    first). In the JSP Generated Servlet, `service()` is inherited from
    `HttpJspBase`, which internally delegates to a method called
    `_jspService(req, res)` — a method generated by the JSP container that
    contains all the output logic of the JSP file.

**Note on `_jspService()`:** Unlike a plain `HttpServlet` where `service()`
dispatches to `doGet()`, `doPost()`, etc. based on the HTTP method, `HttpJspBase`
overrides `service()` to call `_jspService()` *directly*, bypassing that
dispatch chain entirely. This is why all HTTP methods (GET, POST, PUT, PATCH,
etc.) reach a JSP resource without any 405 filtering — there are no
`doGet()`/`doPost()` overrides to restrict access.

**Note:** JSP files have access to certain <u>*implicit objects*</u> that are
pre-instantiated by the JSP container and made available inside `_jspService()`.
The most commonly used ones are:
- `request`: Instance of *HttpServletRequest*. Can be used to access data about
    the request, like using `request.getParameter("email")` etc.
- `response`: Instance of *HttpServletResponse*.
- `out`: Instance of *JspWriter*. This is similar to the `PrintWriter` obtained
    via `response.getWriter()` that we use inside Servlet methods to write data
    to the response stream.
- `session`: Instance of *HttpSession*. Provides access to the session associated
    with the current request.
- `application`: Instance of *ServletContext*. Shared across all requests and
    all users of the web application.

There are 9 implicit objects in total (`pageContext`, `config`, `exception`, and
`page` being the remaining ones), but the three listed first are the ones most
frequently encountered in practice.

## JSP Tag Types

1. Scriptlet Tags `<% ... %>`
1. Expression Tags `<%= ... %>`
1. Declarative Tags `<%! ... %>`
1. Directive Tags `<%@ ... %>`

In this project, we only cover Tag Types 1-3, i.e. Scriptlet, Expression, &
Declarative Tags.

### Scriptlet Tags: `<% ... %>`

- These can embed Java code inside them.
- The code inside is placed inside the `_jspService()` method in the JSP
    Generated Servlet class.
- Since this code is placed inside a method (as stated above), we cannot define
    methods inside Scriptlet Tags.
- We need to use `out.print("<p>..</p>")` or `out.println("<ul><li>...</li></ul>")`
    to write data to the response.
- These can even be used to write conditions and/or loops that wrap around some
    HTML, to conditionally render or repeat a piece of HTML markup.

**Example** — using a Scriptlet Tag to print some HTML to the response, use a
variable declared earlier, and invoke a method declared via a Declarative Tag:

```java
<%
    int a = 3;
    int b = 5;
    String firstname = "John";
    String lastname  = "Doe";

    out.print("<p style=\"color: purple;\">a + b = " + (a + b) + "</p>");
    out.println("<dl>");
    out.println("<dt>firstname</dt><dd>" + firstname + "</dd>");
    out.println("<dt>lastname</dt><dd>"  + lastname  + "</dd>");
    out.println("</dl>");

    power(a, b); // method declared in a Declarative Tag
%>
```

**Example** — using a Scriptlet Tag to open and close a loop, with plain HTML
markup and Expression Tags inside the loop body:

```jsp
<ul>
<% for (int i = 1; i <= 10; i++) { %>
    <li>25 * <%= i %> = <%= 25 * i %></li>
<% } %>
</ul>
```

### Expression Tags: `<%= ... %>`

- These can contain a Java expression whose value is evaluated and printed to the
    response, at the same location where the Expression Tag appears in the JSP source.
- These are a convenience tag to easily print the value of a Java expression,
    without having to write `out.println(...)` calls inside Scriptlet Tags.
- Note that there is **no semicolon** at the end of the expression inside the tag,
    because the JSP container wraps the expression in an `out.print(...)` call — a
    semicolon inside the tag would cause a compilation error in the generated Servlet.

**Example** — printing a request parameter, a concatenated string, and a method
call result:

```jsp
<p>Search query: <strong><%= request.getParameter("search") %></strong></p>
<p>Hello, <em><%= firstname + " " + lastname %></em>!</p>
<p>Result of power(<%= a %>, <%= b %>): <strong><%= result %></strong></p>
```

### Declarative Tags: `<%! ... %>`

- These are used to declare **instance variables** and **instance methods** of the
    JSP Generated Servlet class.
- Unlike Scriptlet Tags, the code inside Declarative Tags is placed *outside* the
    `_jspService()` method — at the class body level. This is why method definitions
    are allowed here, but not inside Scriptlet Tags.
- Instance variables declared here are shared across all requests, since there is
    only one instance of the generated Servlet class (same single-instance model as
    plain Servlets). Treat them with the same caution you would apply to instance
    variables in a Servlet — they are **not thread-safe** by default.

**Example** — declaring an instance variable and an instance method:

```jsp
<%!
    double result;

    public void power(int base, int exponent) {
        result = Math.pow(base, exponent);
    }
%>
```

After this declaration, both `result` and `power(...)` are available anywhere else
in the JSP file — inside Scriptlet Tags, Expression Tags, and other Declarative Tags.
